01 · PRINCIPLES

모두 검증하라고 말합니다.
DECHIVE는 어떻게 검증하는지 보여줍니다.

AI가 답을 만드는 것은 이제 어렵지 않습니다. 문제는 그 답을 왜 믿어야 하는지입니다.

출처가 있는지, 직접 확인할 수 있는지, 어디까지 맞는지, 무엇을 아직 모르는지. 저는 “검증하세요”라는 말에서 멈추지 않고 그 과정을 기록합니다.

01

BEFORE YOU BUILD

만들기 전에 검증합니다.

만들 수 있다는 이유만으로 시작하지 않습니다. 해결하려는 문제가 실제로 존재하는지, 누구에게 필요한지, 지금 만들 이유가 있는지부터 확인합니다.

02

START WITH FRICTION

AI가 아니라 불편에서 시작합니다.

편하기 위해 AI를 쓰는 것이 아니라, 불편을 해결하기 위해 AI가 필요한지 봅니다. AI가 없어도 해결된다면 굳이 AI를 넣지 않습니다.

02 · METHOD

기술보다 이유가 먼저입니다.

새로운 도구를 먼저 고르지 않습니다. 문제를 이해하고, 검증한 뒤, 필요한 만큼만 만듭니다.

04 · CASE STUDY

ASSOCIATION PROCESS

엑셀을 없애려고 만든 게 아닙니다.
엑셀이 사람 사이를 오가는 과정을 없애기 위해 만들었습니다.

BEFORE

  1. 밴드에서 양식 다운로드
  2. 각 동호회가 회원명부 작성
  3. 협회 임원에게 파일 전달
  4. 여러 파일을 다시 취합
  5. 최신본과 누락 여부 확인
  6. 도 단위 협회 제출용으로 재정리
REDESIGN →

AFTER

  1. 사이트에서 직접 등록·신청
  2. 데이터 자동 저장
  3. 필요한 승인과 알림 연결
  4. 협회가 한 화면에서 확인
  5. 필요한 시점에 Excel/HWP 생성
  6. 기존 제출 형식은 그대로 유지

좋은 자동화는 사람을 없애는 것이 아니라, 사람이 굳이 할 필요 없는 전달과 반복을 없애는 것이라고 생각합니다.
