01 · AUTOMATION STRUCTURE

자동화의 뼈대부터 본다

도구나 AI부터 고르지 않습니다. 반복되는 일을 먼저 관찰하고, 프로그램이 처리할 수 있는 구조로 바꿉니다.

INPUT

입력

영상, 제목, 본문, 예약 시간처럼 프로그램이 받아야 하는 재료.

RULE

규칙

Instagram은 큰 제목, TikTok은 Hook처럼 사람이 반복해서 판단하던 기준.

TRANSFORM

변환

자막, CTA, BGM, 커버, 게시글을 플랫폼에 맞게 바꾸는 과정.

EXECUTE

실행

자동 게시, 예약 게시, 다운로드, 업로드 패키지 생성 같은 실제 행동.

VERIFY

검증

성공·실패·처리 중 상태와 실제 게시 결과를 확인하는 단계.

핵심: 자동화는 버튼을 줄이는 일이 아니라, 사람이 반복하던 판단과 행동을 규칙으로 바꾸는 일입니다.

03 · BUILD IT STEP BY STEP

기능 하나를 추가하면 무엇이 바뀔까?

화면에 입력칸 하나를 추가하는 것과 기능 하나를 만드는 것은 다릅니다. 데이터의 시작부터 결과까지 길을 연결해야 합니다.

STEP A

제목 추가

영상만 있던 프로그램에 새로운 데이터가 생깁니다.

{ video } ↓ { video, title } UI → 상태 → 저장 → 결과 → 검증
STEP B

플랫폼 선택 추가

여기서 처음으로 하나의 흐름이 여러 갈래로 나뉩니다.

input ├─ Instagram ├─ TikTok └─ Naver Clip
STEP C

규칙 추가

사람이 매번 하던 판단을 데이터와 프리셋으로 바꿉니다.

Instagram: opening = title cta = save TikTok: opening = hook cta = comment
04 · LOCKED LEARNING FLOW

왜 기능을 잠가두나?

완성된 프로그램을 처음부터 보여주면 사용법만 기억합니다. 하나씩 열면 프로그램이 왜 그렇게 만들어졌는지를 이해하게 됩니다.

🔓
01 영상 입력

자동화의 입력부터 정의한다.

🔒
02 제목 추가

새 입력 데이터가 생기면 저장·처리·출력도 함께 바뀐다.

🔒
03 게시글 추가

역할이 다른 데이터는 분리해서 저장한다.

🔒
04 플랫폼 선택

조건과 분기가 생긴다.

🔒
05 플랫폼 규칙

반복 판단을 프리셋으로 바꾼다.

🔒
06 실행·검증

실행 요청이 아니라 실제 결과까지 확인한다.

05 · PRACTICE

이제 직접 자동화를 만들어봅니다.

영상 입력부터 시작해 제목, 게시글, 플랫폼, 규칙, 실행을 하나씩 잠금 해제하면서 프로그램이 자라는 과정을 직접 확인합니다.
