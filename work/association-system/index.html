PROCESS NOTE 01 / ADMINISTRATIVE WORK

없애야 했던 것은 엑셀이 아니라,
엑셀이 오가는 과정이었습니다.

회원등록과 이적 신청에 쓰이는 문서 자체가 문제는 아니었습니다. 여러 사람을 거치며 파일을 전달하고 취합하고 최신본을 확인해야 하는 반복이 실제 불편이었습니다.

01 / PROBLEM

여러 파일을 모으는 일이 반복됐습니다.

회원등록 때마다 각 동호회에서 엑셀 양식을 작성하고, 담당자가 파일을 받아 하나로 모아야 했습니다. 이적 신청은 별도의 문서와 승인 과정을 거쳤습니다.

문서를 하나 더 만드는 것보다 어려운 일은 서로 다른 곳에서 온 파일과 상태를 계속 맞추는 일이었습니다.

02 / DECISION

판단은 남기고, 전달은 줄이기로 했습니다.

승인이 필요한 부분까지 자동으로 처리할 이유는 없었습니다. 대신 정보 입력과 신청 상태 확인을 한곳에서 할 수 있도록 흐름을 바꾸고, 담당자가 반복해서 파일을 주고받는 과정을 줄이는 방향을 선택했습니다.

03 / CHANGE

입력·확인·출력을 분리했습니다.

회원 정보 등록과 변경 신청을 다루는 화면, 신청 상태를 확인하는 흐름, 필요한 문서를 생성하는 단계를 구분해 다시 설계했습니다. 최종 제출처에서 엑셀이나 HWP를 요구한다면 그 형식은 유지하는 것이 현실적이라고 판단했습니다.

04 / CHECK AGAIN

실제 운영에서 계속 확인할 문제도 남아 있습니다.

입력 방식만 바꿨다고 행정 업무가 전부 개선되는 것은 아닙니다. 권한이 필요한 구간, 누락되는 정보, 현장에서 익숙한 문서 형식과의 호환성은 운영 흐름에서 계속 확인하고 수정해야 합니다. 개선 중인 작업을 완성된 성과처럼 소개하지 않습니다.
